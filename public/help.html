Cloudflare Admin Toolkit

도움말 — Cloudflare 에 설치하기

이 도구를 새 Cloudflare 계정에 처음 설치하는 방법입니다. 명령 하나로 설치하는 방법과, 무엇을 만들고 변수 · 시크릿에 어떤 이름과 값을 넣는지 정리했습니다.
만드는 것
  • API 토큰 — 관리할 도메인이 있는 계정에서 발급. 도구가 도메인·IP 룰을 바꿀 때 쓰는 열쇠
  • Worker 1개 — 이 도구의 코드와 화면 (src/, public/)
  • KV 1개 — 그룹 · 상태 캐시 · 변경 이력 · OTP 목록 · IP 분류 규칙 · 설정 값을 저장
  • 변수 — 대상 서버 IP 같은 보통 값. wrangler.jsonc 파일에 적는다
  • 시크릿 — 토큰 · 비밀번호처럼 숨길 값. 파일에 적지 않고 명령으로 넣는다

모두 무료 요금제로 됩니다 (Workers 하루 10만 요청, KV 쓰기 하루 1,000회).

빠른 설치 — 명령 하나

대시보드에서 하나씩 만들 필요 없이, 샘플 파일의 빈 칸을 채우고 명령 하나를 실행하면 됩니다. 대시보드에서 직접 하는 일은 API 토큰 만들기뿐입니다.

① API 토큰 (대시보드)→ ② 샘플 파일 → setup.env→ ③ 빈 칸 채우기→ ④ node setup.mjs
  1. API 토큰 만들기 — 1단계 표의 권한으로
  2. 샘플 파일을 소스 폴더에 setup.env 로 저장 샘플 파일 내려받기
    또는 소스 폴더에서 node setup.mjs --init — 샘플은 모두 빈 칸입니다
  3. setup.env 의 빈 칸 채우기 — 필수는 WORKER_NAME · CF_API_TOKEN · PASSWORD_PREFIX · SERVER_IP. wrangler 에 계정이 여러 개면 ACCOUNT_ID 도
  4. 소스 폴더에서 실행
node setup.mjs --dry-run      # 먼저 확인만 — 값 · 토큰 · 로그인 · 빌드 검사, 아무것도 만들지 않음
node setup.mjs                # 설치 (다시 실행하면 업데이트)
스크립트가 하는 일
  • 값 검사, 토큰 확인 (도메인이 몇 개 보이는지 · IP Rules 권한)
  • wrangler 로그인이 안 돼 있으면 브라우저를 열어 로그인
  • KV 만들기 → 배포 (시크릿 함께, SESSION_SECRET 은 자동) → 주소와 첫 로그인 안내
  • 올린 시크릿은 setup.env 에서 지웁니다. 다시 실행할 때 비워 두면 이미 올린 값을 그대로 씁니다
  • 값을 고친 뒤 다시 실행하면 새로 만들지 않고 업데이트합니다
안전장치 — 소스 폴더의 wrangler.jsonc(운영 중인 Worker)는 건드리지 않고 설치용 wrangler.setup.jsonc 를 따로 만듭니다. wrangler.jsonc 의 Worker 이름이거나, 이 스크립트가 만들지 않은 기존 Worker 이름이면 덮어쓰지 않고 멈춥니다.

1API 토큰 만들기 (대시보드)

관리할 도메인이 있는 계정으로 로그인 → 오른쪽 위 프로필 → My Profile → API Tokens → Create Token → Custom token. 토큰 값은 만들 때 한 번만 보이니 바로 복사해 둡니다.

도메인 토큰 → 시크릿 CF_API_TOKEN

항목값쓰는 곳
PermissionsZone · Zone · Read도메인 목록
Zone · DNS · Edit프록시 (Proxied ↔ DNS only)
Zone · Zone Settings · EditSSL 모드 · Tiered Cache · Smart Tiered Cache
Zone · Cache Rules · Edit정적파일 캐시 규칙
Zone ResourcesInclude · All zones from an account · (그 계정)새로 추가한 도메인도 자동으로 포함
Client IP Filtering비워 둠Workers 는 나가는 IP 가 바뀌어서 걸면 안 됨

IP Rules 토큰 → 시크릿 CF_IP_TOKEN 선택

항목값쓰는 곳
PermissionsAccount · Account Firewall Access Rules · Edit계정 IP 룰 보기 · 삭제 · Action 변경
Zone · Firewall Services · Edit자산존의 Allow 예외 룰
Zone · Zone · Read계정 ID · 자산존 ID 자동으로 찾기

따로 만들지 않고 도메인 토큰에 위 권한을 추가해도 됩니다. CF_IP_TOKEN 이 없으면 IP Rules 도 CF_API_TOKEN 을 씁니다. 이미 쓰던 토큰에 권한을 더할 땐 토큰 Edit → Add more — 토큰 값은 그대로라 다시 넣을 필요가 없습니다.

2준비 · wrangler 로그인

  • Node.js (LTS) 설치. wrangler 는 npx 로 바로 실행되므로 따로 설치하지 않아도 됩니다
  • 이 도구의 소스 폴더를 받아서 그 폴더에서 아래 명령을 실행합니다
npx wrangler login      # 브라우저가 열리면 Worker 를 둘 계정으로 허용
npx wrangler whoami     # 로그인한 계정과 계정 ID 확인 (계정이 여러 개면 여기서 고른다)

Worker 를 둘 계정과 도메인이 있는 계정은 달라도 됩니다. 토큰만 도메인 계정에서 만들면 됩니다.

3KV 만들기

npx wrangler kv namespace create BDM_KV

출력에 나오는 id 를 다음 단계의 kv_namespaces 에 넣습니다.

wrangler.jsonc 의 KV id 자리에 <...> 같은 자리표시가 남아 있으면 이 명령이 Authentication error 10000 으로 실패합니다. 그럴 땐 kv_namespaces 블록을 잠시 지우고 만든 뒤 다시 넣습니다.

4wrangler.jsonc — 변수

소스 폴더의 wrangler.jsonc 에서 이름 · 계정 ID · KV id · 변수를 바꿉니다. 나머지는 그대로 둡니다.

{
  "name": "my-cf-admin",                 // Worker 이름 → 주소 my-cf-admin.<서브도메인>.workers.dev
  "account_id": "<Worker 를 둘 계정 ID>",  // 2단계 whoami 에서 본 값. 적어 두면 다른 계정에 잘못 배포되지 않음
  "main": "src/worker.js",
  "compatibility_date": "2026-09-01",
  "workers_dev": true,
  "assets": { "directory": "./public", "binding": "ASSETS", "run_worker_first": true },
  "kv_namespaces": [
    { "binding": "BDM_KV", "id": "<3단계에서 나온 id>" }    // binding 이름은 BDM_KV 그대로
  ],
  "vars": {
    "SERVER_IP": "203.0.113.10",
    "DEFAULT_GROUP": "",
    "CONCURRENCY": "6",
    "CACHE_TTL_MINUTES": "10",
    "MAX_ZONES_PER_CALL": "5",
    "OTP_ISSUER": "CF Admin",
    "IP_PAIR_ZONE_NAME": "",
    "IP_RATE_BUDGET": "900"
  }
}

값은 모두 따옴표 안의 문자열로 적습니다. 설정 메뉴 칸이 가능 인 것은 배포한 뒤 설정 화면에서도 바꿀 수 있고, 여기 적은 값은 그때 기본값이 됩니다.

이름예뜻설정 메뉴
SERVER_IP203.0.113.10DNS · SSL/TLS 일괄 변경 대상 서버 IP. 이 IP 를 가리키는 A/AAAA 레코드만 바뀌고 나머지는 보호가능
DEFAULT_GROUP중요고객처음 열 때 보이는 그룹 탭. 그룹이 없으면 비워 둠가능
CACHE_TTL_MINUTES10도메인 SSL · 프록시 상태를 다시 읽기 전까지 기억하는 시간(분)가능
CONCURRENCY6Cloudflare API 를 동시에 부르는 수—
MAX_ZONES_PER_CALL5변경 요청 한 번에 넣는 도메인 수. 무료 요금제는 요청 1건당 외부 호출 50회 제한이라 5 권장—
OTP_ISSUERCF Admin구글 OTP 앱에 보이는 이름. 콜론(:) 금지가능
IP_PAIR_ZONE_NAMEexample.com404 가드가 IP 마다 Allow 예외 룰을 만드는 자산존. 쓰지 않으면 비워 둠 → 계정 IP 룰만 관리가능
IP_RATE_BUDGET900IP Rules 화면이 5분 동안 쓰는 API 호출 상한. Cloudflare 한도 1,200회를 대시보드 등과 나눠 씀가능
IP_ACCOUNT_ID
IP_PAIR_ZONE_ID		(비움)보통 적지 않음 — 토큰으로 자동으로 찾음. IP Rules 토큰이 여러 계정에 걸쳐 있을 때만 계정 ID 를 적음—
관리 대상 도메인에 route 를 걸지 마세요. 그 도메인을 DNS only 로 바꾸는 순간 이 도구도 끊깁니다. 주소는 workers.dev 나 Custom Domain(8단계)을 씁니다.

5배포

npx wrangler deploy

Worker 가 없으면 새로 만들어지고, wrangler.jsonc 의 변수 · KV 연결이 함께 들어갑니다. 끝나면 주소 https://<이름>.<서브도메인>.workers.dev 가 나옵니다. 시크릿을 넣기 전에는 열어도 "시크릿이 설정되지 않았습니다" 가 보입니다.

6시크릿 넣기

이름값
CF_API_TOKEN필수1단계에서 만든 도메인 토큰
PASSWORD_PREFIX필수로그인 비밀번호 앞부분. 실제 비밀번호 = 접두어 + ! + 오늘 날짜 두 자리(한국 시간). 예) 접두어 abc, 5일이면 abc!05. 대소문자 구분
SESSION_SECRET필수로그인 쿠키 서명용 긴 임의 문자열. 외울 필요 없음. 바꾸면 모두 로그아웃됨
CF_IP_TOKEN선택IP Rules 토큰. 없으면 CF_API_TOKEN 을 씀

하나씩 넣기 — 명령을 실행하면 값을 물어봅니다 (화면·기록에 남지 않음):

npx wrangler secret put CF_API_TOKEN
npx wrangler secret put PASSWORD_PREFIX
npx wrangler secret put SESSION_SECRET
npx wrangler secret put CF_IP_TOKEN        # 선택

SESSION_SECRET 에 넣을 임의 문자열 만들기:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

한 번에 넣기 — JSON 파일에 적어서 올리고, 파일은 바로 지웁니다:

# secrets.json  {"CF_API_TOKEN": "...", "PASSWORD_PREFIX": "...", "SESSION_SECRET": "..."}
npx wrangler secret bulk secrets.json
대시보드에서 넣을 땐 Worker → Settings → Variables and Secrets → Add 에서 Type 을 Secret 으로 고릅니다. Text 로 넣은 값은 다음 wrangler deploy 때 wrangler.jsonc 의 변수로 덮여 사라집니다.

7첫 로그인 · 2단계 인증

  1. 배포 주소를 열고 비밀번호(접두어!오늘날짜)로 로그인
  2. 위쪽 2단계 인증 → 이름 입력 → 구글 OTP 앱으로 QR 스캔 → 앱의 6자리 입력
  3. 처음 등록한 사람이 관리자가 됩니다. 관리자만 다른 사람 OTP 추가 · 사용중지 · 삭제와 설정 변경을 할 수 있습니다
OTP 를 등록하기 전에는 비밀번호를 아는 누구나 로그인해서 설정을 바꿀 수 있습니다. 배포 직후 바로 등록하세요.

8도메인 붙이기 (선택)

Worker 와 같은 계정의 도메인이면: Worker → Settings → Domains & Routes → Add → Custom domain 에서 admin.example.com 같은 이름을 넣습니다. DNS 레코드와 인증서는 자동으로 만들어집니다.

다른 계정의 도메인이면 Custom domain 을 바로 붙일 수 없습니다 (도메인과 Worker 가 같은 계정이어야 함). 도메인 계정에 아래 몇 줄짜리 전달용 Worker 를 만들고, 그 Worker 에 Custom domain 을 붙입니다.

export default {
  async fetch(request) {
    const url = new URL(request.url);
    url.hostname = "<이름>.<서브도메인>.workers.dev";   // 이 도구의 workers.dev 주소
    return fetch(new Request(url, request));
  },
};

이 경우 요청 수는 두 계정 모두에서 1건씩 셉니다. 도구의 Worker 이름을 바꾸면 위 주소도 같이 바꿔야 합니다.

9코드 업데이트

npx wrangler deploy
  • 시크릿 · KV 데이터(그룹 · 이력 · OTP · 설정 메뉴에서 바꾼 값)는 그대로 남습니다
  • wrangler.jsonc 의 변수는 파일 값으로 다시 들어갑니다. 설정 메뉴에서 바꾼 값은 그 위에 덮이므로 계속 유지됩니다
  • Worker 이름은 대시보드에서 바꾸고 wrangler.jsonc 의 name 을 맞춥니다. 파일만 바꾸면 시크릿 없는 새 Worker 가 따로 생깁니다

10로컬 실행 (선택)

Cloudflare Workers 가 안 될 때를 대비해 PC 에서 같은 화면을 띄울 수 있습니다. 로그인 없이 127.0.0.1 에서만 열립니다.

cp config.example.json config.json     # token (필수), ipToken (선택) 등을 채운다
node server.mjs                         # → http://127.0.0.1:8790

로컬은 데이터를 data/ 폴더에 따로 저장하므로 Workers 쪽 그룹 · 이력과는 공유되지 않습니다.
